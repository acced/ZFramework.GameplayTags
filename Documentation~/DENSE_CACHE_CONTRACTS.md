# 有界栈缓存：语义、证明与验收边界

本轮主实验固定提交3854fda5c923e44cadb081e774d708030cf1e2a3，基线PR20实际计时源码0d097a1546c51ea3676ef35817428f346da46293。本文只说明实现，不构成性能通过结论。

## 入口与所有权

公开AppendTags先Require；AppendCore先处理同对象、空源、空目标和两侧表示，再进入Dense源/Micro目标的私有追加。已有代码保证同一注册表、非空、稳定源、输入输出不共享成员缓冲。内部不重复名称解析或完整结构验证。无并发修改，Count始终是已经建立的不变量。

新分派只检查source.count<=32。每条有效Micro16记录的掩码至少一位，故有效记录数量r<=源成员数量<=32。这是缓存容量安全界，不是证明任何N<=32都更快。N>32但记录少时保守不使用缓存，不额外扫描决定是否可缓存。

栈缓存只属于NoInlining的小助手单次调用；每个调用返回后不持有Span引用。调用方循环不直接stackalloc，不把栈存储写入对象、闭包、异步状态或其他所有者。使用安全Span下标；没有指针、SkipLocalsInit、全局池、共享临时区或COW。32条uint载荷为128B，完整栈帧必须按实际目标反汇编另算，不能忽略保存寄存器、对齐和检查。

## 首遍得到准确结果记录长度

令目标有效键序列为A，源记录键序列为B。两者严格递增且每键唯一。首遍按B递增推进目标at，at只前进到第一个A[at]>=B[j]的位置。若不存在相等键，结果多一条记录；否则只合并成员位，不增加记录数。因此length=|A union B|准确，且未修改任何旧目标记录。

记录n增加时先写records[n]，最后只读[0,n)。即使栈内其他位置未初始化，也不会读取。输入Count错误属于被破坏的内部不变量，不通过临时修复掩盖。

## 反向写入安全

首遍确定最终长度后，write从length-1，read从used-1，pending从n-1开始。每步写出两侧剩余键中较大的；键相等只写一条合并记录，两个读指针同时后退。未处理结果记录数不小于未处理目标记录数，因此write>=read，不能覆盖尚未读取的目标。

pending耗尽时，没有未写入的源键；目标剩余前缀就是结果前缀，原地保留，不额外复制。源来自独立的操作局部缓存，目标写入不会改变它。

准确成员数不是记录数。最终Count=原目标Count+源Count-Pop(原交集)。相同键下不同成员位不计重复；每个相同键仅归并一次，因此重叠不重复扣减。调用期间无外部观测半成品的约定；对错误输入的公开验证保留。

## 容量与异常边界

准确length装得下时不扩容。装不下时仍沿原ReserveEntries(EntryCapacity+1)阶梯增长，最终容量和总托管分配字节与逐项插入相等，不用较大的上界预约换排名。这里保留旧实验合同是为了隔离算法变量，不是宣称多次扩容本身最优。

内存耗尽时的中途成员修改顺序不承诺与旧逐项插入相同，也不新增强回滚。缓存增加固定局部栈空间，在异常的调用栈压力下仍有栈耗尽风险；真正Unity/IL2CPP和设备栈预算另验。

## 已知需要专门否证的风险

1. 128B临时载荷与Span写读、额外调用可能比极小集合逐项插入更贵。
2. 内部缺口引发的二次Dense遍历被消除，但一次全域扫描仍存在，不意味着小集合应选择Dense表示。
3. 小源只命中大目标的前缀时，缓存算法当前会反向读写目标已有尾部；没有新键并不自动跳过。这是新增实际工作，必须通过不等规模输入验收。
4. 大源fallback方法体未变，但新增入口/方法位置仍可能改变实际性能；不能删掉这些回退。
5. 32/33边界的明显变化可能是成本不连续，而不是正确性错误。边界两侧都测，不能用N8单表外推。

## 证据层次

主性能构建：fixed/monotone/stream/dispatch/cache32五个独立二进制，全部新建/复用和同二进制A/A。dispatch仅给原stream加相同Count分派和NoInlining小助手，分离包装层成本。

独立工作量构建：只统计实际读字、输出、后缀搬移、缓存读写，不计时，也不进入性能排名。原源码哈希必须对应主计时两个架构，不能拿旧版本诊断解释新版本。

额外不等规模构建：固定主算法，目标128/4096、源1/8/32/33，前缀子集、前缀新增位、中间子集、尾部输入；单独标明运行和容量，不拼接绝对耗时。

未完成真实Unity/IL2CPP/Burst/手机、多角色冷缓存、长期峰值内存和全部历史库对照之前，不宣称全库发布或四项全面领先。所有未通过测点、失败的首次来源断言与修复都要进入最终报告。
