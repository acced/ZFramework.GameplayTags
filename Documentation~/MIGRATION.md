# 2.0 迁移说明

这一版重写运行时数据结构，并保留主要 public API、`GameplayTags` 命名空间、Unity 标签名称字段和容器序列化字段。它不是二进制兼容替换；请重新编译依赖项目。

## 明确改变的行为

| 项目 | 新行为 / 迁移方式 |
| --- | --- |
| 运行时 ID | 真正的 DFS 前序编号，按 ordinal 兄弟节点顺序分配。不能沿用旧进程或旧构建保存的数字 ID；按名称重新解析。 |
| 容器枚举 | 无序紧凑存储，删除可能改变顺序。UI 或网络编码需要排序时在边界显式排序。 |
| 名称顺序 | 区分大小写的 ordinal 顺序；查询本来就是区分大小写的，现在注册和编辑器也保持一致。 |
| 相等性 | `Equals(object)` 只比较 GameplayTag；与字符串比较请使用 `tag.Name`，或先解析字符串得到标签。修复跨类型比较与哈希码不一致的问题。 |
| Intersection | 交集先作用于显式标签，再计算祖先。例如 `{A.B}` 与 `{A.C}` 的交集为空，不产生“显式为空、隐式还有 A”的状态。 |
| Intersection 输出 | 输出会被替换，可以是非空容器，也可以与任一输入是同一个对象。 |
| HasAll 的两个条件集合 | holder 必须同时满足两组全部显式条件，不再取两组条件的交集。 |
| 两个 holder 联合满足条件 | 每个条件可由任一 holder 满足，无需分配临时容器；两个空 holder 不能满足非空条件。 |
| Utility 三参数调用 | `GameplayTagContainerUtility.HasAll(a, b, query)` / `HasAllExact(a, b, query)` 改为静态调用，不再是扩展方法。`holder.HasAll(queryA, queryB)` 则表示同时满足两组条件。 |
| Copy | 空来源会清空目标；复制自己是 no-op。计数容器复制到普通容器时只保留存在性。 |
| Union | 正确处理任意一方为空，包括右侧空集合。 |
| RemoveTags | 缺失标签是 no-op，不会提前中断剩余标签的删除；支持同源别名。 |
| 计数事件 | 删除正确派发全局 AnyCountChange；Clear 会派发两个类别的归零事件。 |
| 事件重入 | 当前批次后追加重入通知；回调异常传播，已提交状态保留，未派发通知被释放。 |
| 父容器贡献 | Parent 变更、Clear、部分 RemoveTags 按真实显式次数更新，不再丢失或多删次数。父链无环，调用者不能从父容器直接移除子容器拥有的贡献。 |
| 序列化 | 修正 .NET callback 属性和 StreamingContext 签名；实现 Unity callback。按名称恢复 ID，不保存运行时数组。 |
| 源码生成器 | 通过语义读取声明，支持别名、常量、限定名和属性覆盖；`Tag` 不再截断路径。关键字、数字开头、保留成员名和同名嵌套类有确定性转义。 |
| 重复声明 | flags 合并，description 选择 ordinal 最小值，避免程序集扫描顺序决定结果。显式声明的父标签保留自己的 flags；自动父标签合并后代 flags。 |

## 性能契约

删除一般参数防御、日志和重复校验后，以下前提由调用者负责：有效非 None 标签、正的 amount、删除量不超出已有次数、无环父链、无并发修改、无修改中枚举、正确释放池对象。违反前提可能导致错误数据或 CLR 异常，不保证友好的错误提示。

保留一个冷路径防护：已经初始化的全局注册表不能被重新初始化，否则所有存活标签 ID 都会失效。显式调用的 `ValidateName` 仍可在内容导入或编辑阶段报告无效名称。计数回调中保留 finally 清理，保证回调抛异常不会永久污染事件派发状态。

`GameplayTag` 为兼容 Unity 名称序列化仍含有字符串引用，**并非 4 字节结构体**；容器内部仅存储 32 位 ID 和计数。具体类型的 foreach 返回结构体枚举器；通过 `IEnumerable<GameplayTag>` 使用仍可能装箱。

## 升级检查

1. 重新编译依赖，删除自己对旧 internal 列表实现的拷贝或反射依赖。
2. 将持久化数字 ID 改为名称，或在加载时从稳定业务 ID 映射到当前标签。
3. 对依赖排序枚举的调用方增加明确排序。
4. 根据上表检查 Intersection、HasAll、全局 count events 和父容器次数的预期。
5. 在目标 Unity 版本和后端运行项目自身场景，特别是序列化资产与 Editor 窗口。
6. 从 Git 包升级时保留随包提交的 `.meta`；不要重新生成 GUID。此前手工复制到 Assets 并由本地 Unity 生成过 GUID 的项目，应保留已有脚本资产的引用或执行明确的引用迁移。
