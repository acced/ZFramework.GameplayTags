# GameplayTags：解除 Dense-only 后的性能研究方向

日期：2026-10-01。当前实验 PR #10。

## 已改变的约束

用户明确解除“全面使用 Dense、不允许 Sparse”的限制。现在允许直接整数数组、位图、分块压缩、哈希等结构参加比较，目标是完整操作成本而不是某一种表示形式。正确性、独立结果、准确 Count、容量与别名契约、准备后的零托管分配仍保留。此次没有把任意全局标签改成受限局部域。

## 首轮不是重新造容器，而是恢复一个可解释的对照

固定 Auto 提交：`84729cc3b6e1b4681328806df2d7c8a1d8f568f6`。
固定 Micro 提交：`9be85fcd1f8d1f594ceb5bc98f2ce234b398e0e0`。
DenseFusion 后端：`d45f21ffc5858a7ce9be68af9322924a774e40b4`。
Micro DirectArray 来源：`2866adfc6bfc21a11177c6b5873fbc54afebfe13`。

旧 Auto 的成员只有一份有效存储：有序 int[] 或连续 ulong[]。对分散小集合，数组直接保存整数，不需要区间地址解码、成员掩码及 PopCount；成员数就是有效数组长度。这消除了此前为了维持纯位图语义而支付的工作。Dense 则保持顺序位运算优势。

本轮没有修改仓库生产 Runtime，而是在隔离构建中替换同名 RuntimeTagSet，运行原来的完整 Runtime、层级、Query 和编辑器代码生成测试。不是只测一个不能接入项目的集合小模型。

### 独立变量

| 标签 | 唯一改变 |
|---|---|
| auto / autoAA | 同一个二进制，两个报告身份；测量 A/A 差异 |
| dense | Dense 并集、追加、删除连接到既有融合写出和准确计数内核 |
| simd | 短有序整数数组的布尔成员查询；插入与层级下界仍使用原 IndexOf |
| copy | 直接建立独立结果数组，保留源容量、表示和空数组策略 |
| combined | 三项实际合并；不能按行挑不同版本的赢家 |
| direct | PR8 微位图直接数组版本，仅作为对照 |

独立变量的代码、生成后的全部 C# 和差异均归档。没有同时改阈值、内联数量、成长公式或数据分布。Vector 查询的 32 项上界是待验证的试验选择，不是声称已得出最优阈值。

## 研究依据，不是排行榜背书

### 稀疏数组与位图

Roaring 官方说明：随机分散的小整数集合可能最适合普通数组；小编号域可直接用不压缩位图。Roaring 的完整实现通过数组、位图和 run 容器处理局部不同分布。但该项目的主要用例包含很小的角色集合，不能假定完整 Roaring 的目录与容器成本总值得。

来源：https://roaringbitmap.org/about/

### 小集合内联

LLVM 的 SmallSet/SmallVector 将少量元素直接放在对象中，从而省去单独分配；官方同时提醒对象本身会变大。它是后续构造优化候选，不是本次实现。验证时必须同时计算空集合、大量长期存活容器和转出内联时的成本，不能只展示八成员输入。

来源：https://llvm.org/docs/ProgrammersManual.html#llvm-adt-smallset-h
来源：https://llvm.org/docs/ProgrammersManual.html#llvm-adt-smallvector-h

### 有序集合内核

Lemire、Boytsov、Kurz 的 SIMD Compression and the Intersection of Sorted Integers 研究 SIMD 和 Galloping。在本项目中，等规模输入的线性归并与极端不等规模输入的跳跃搜索应分开比较。论文中的解压缩、交集吞吐并不是本项目的新建并集成绩。

来源：https://arxiv.org/abs/1401.6399

CRoaring 研究同时包含数组并集、交集、差集等 SIMD 算法，适合作为大有序数组内核参考；不能用 C/C++ 的裸内核结果保证 C# 或 IL2CPP 的整体调用收益。

来源：https://arxiv.org/abs/1709.07821

### 分布自适应

run 容器适合长连续区间，但持续随机增删会产生区间拆分和合并。只有真实数据呈现稳定的长区间，并且包括更新成本后仍受益，才有理由增加第三种表示。

来源：https://arxiv.org/abs/1603.06549

### 测量可靠性

LLVM 明确区分测量噪声和系统性偏差：低噪声不是充分条件。A/A 只是本轮增加的诊断，不等于已经解决全部偏差。源码相同却速度不同不应自动计为算法收益，也不能自动丢弃。

来源：https://www.llvm.org/docs/Benchmarking.html

## 下一步怎样选表示，而不是把一个阈值当作全部优化

当前 Auto 比较 `8 * WordCount` 与 `4 * capacity`；这是成员缓冲的字节交叉点。令 U 为实际注册编号数，W=ceil(U/64)，近似交叉点为 N=U/32。它不是 CPU 交叉点。

构造型负载要计入分配、零初始化、合并、写出和准确计数；长期复用集合要计入查询与增删，不能只看一次构造。提升 Dense 内核会改变 CPU 交叉点，却不改变数组与位图的字节交叉点。

后续表示选择需要对相同输入比较强制 Array、强制 Dense 及最终同一条 Auto 规则。强制模式用于定位交叉点，不能把每行最佳强制模式拼成一个“Auto 全胜”的表。

在核心热路径零分配合同下，不应让单次 Add 在容量足够时偷偷发生全结构转换。表示转换应置于明确的构建/准备或可观察的批量边界，且成本计入对应操作；是否修改当前“构造时选定”合同须独立验收。

## 候选优先顺序

1. 首轮：恢复整数数组＋Dense，分别验证执行内核和复制构造，不改变公共语义。
2. 第二层：阈值与输出表示的成本模型；同一实现运行全部矩阵。
3. 需要进一步压低很小集合构造成本时，单独比较有限内联整数槽位；不把大型对象成本隐藏。
4. 只有在“全局大、局部有多个稠密簇”的数据中，才比较 Roaring 风格分块。小集合必须有无需目录的路径。目录、每块对象、转换与析构/释放成本全部纳入。
5. 只有查询可证明不可变的对象，才评估 FrozenSet 等不可变结构；不能拿它代替可变角色标签集合。

不重新引入全局对象池、共享可变临时缓冲、延迟 Count 或基于测试固定输入的特殊常量。

## 验收结构

历史四项：预解析精确查询、独立 Union、真实 Copy+Append、真实 Copy+Remove。Into 单独列。基准中的原始 Action 调用和 object sink 保留，所以本轮没有改变结果消费方式，也没有引入结构体装箱争议。

A/A 使用同一 DLL，随机交错各进程顺序。保存三轮原始七样本、输入摘要、分配、各代 GC 次数、运行时与 CPU 信息、生成源码摘要。诊断用反汇编不计入性能样本。

当前样本关系仍为半重叠与删除已有一半子集；完整不同重叠率、持续变更、峰值和常驻内存未被这轮覆盖。Linux ARM64 .NET 不等于 Unity ARM64 IL2CPP，也不等于手机热状态。

## 状态
