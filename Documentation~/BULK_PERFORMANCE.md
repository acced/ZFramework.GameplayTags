# Copy、Union 与显式 Intersection 的批量优化

本次针对 Unity 实测反馈中的三项回退修改运行时：复用容器 Copy、创建 Union、创建显式 Intersection。公开调用方式保持一致，返回结果仍可独立修改；计数来源只按不同显式标签各贡献一次。

**本轮独立对照固定为首次重写提交 `3f10ba49433d8b5fdd394a7ac2f1dce32800fd7c` 与本次实现，运行平台为 .NET 8 x64。** 每项 14 个独立进程样本，前后版本交叉执行，报告中位数。Unity 6000.3.14f1、Mono、IL2CPP 和 Alex 对照没有在本环境执行。

## 实现改动

### 1. Copy：连同有效哈希索引一起复制

旧实现先逐个清除目标的桶，再复制条目与显式索引，最后重新哈希每个来源标签。原本可以直接复制的索引被重复计算。

现在将**分配的桶数组容量**与**正在使用的桶前缀**分开。来源和目标采用相同的有效 mask 与 dense 顺序时，条目、显式索引和有效桶前缀可以整块复制。目标即使预留了 8 倍容量，也能使用来源的有效前缀，省去逐项清桶与重新哈希。来源与目标的数组仍独立。

来源的有效桶数超过 `max(32, 8 × 来源总标签数)` 时，改建紧凑索引，避免为了很少的数据复制巨大的稀疏表。有效 mask 为 0 时采用原有线性小集合路径；重新增长为较大的哈希表前，会清空即将重新使用的整个前缀，再构建索引，保证旧尾部桶不重新出现。

数据量 T、显式数量 E、有效桶数 B 下，直接路径成本为 `O(T + E + B)`，这里 B 有密度上界；稀疏来源回退为期望 `O(T + E)` 的紧凑重建。自复制仍为 `O(1)`；空来源清空目标仍与目标存量有关。Copy 的成本不会因为目标单纯预留了很大的容量而扩大。

### 2. Union：合并共享父标签的待处理贡献

优先复制普通集合种子；两者同为普通或计数来源时，优先选较大的祖先闭包。计数种子先规范化为普通集合，追加来源按不同显式标签处理。

对新增显式标签，先提交自身的一次贡献，仅把直接父标签加入待处理队列。多个子标签同时指向同一父标签时，先累加该父标签的 pending，再将合计次数向上级传递。仍需为每个新叶标签定位直接父分组；将共享分组的贡献合并后再向上转发，减少对根等更高层祖先的重复查找。

队列存储 dense index；Union 只插入，所以扩容不会使这些 index 失效。队列阶段临时复用条目显式计数字段的高位，低位仍表示显式存在；父标签在已经排队后升级为显式标签，也会保留待处理贡献。方法返回前全部恢复到普通集合的 0 / 1 显式次数，没有新增每标签字段。

收集阶段每个新增显式标签最多使一个父节点入队；排空阶段出队一个、最多再入队一个，因此峰值队列项数不超过追加输入的 E。最多 8 个显式项的追加继续使用直接路径，以控制小集合和少量深层标签的开销。

FIFO 并不保证每个祖先只处理一次。深链上若包含很多不同深度的显式祖先，父节点可能再次入队，贡献转发部分最坏仍为 `O(Σ 新增显式标签深度)`，与逐项增量维护同阶。完整 Union 还要支付种子的复制或规范化，以及追加输入全部 E 个显式项的成员检查；即使完全重叠，这些成本仍然存在。这里的收益来自合并共同处于 pending 状态的贡献，不能把它写成任意树形下的 `O(T)` 保证。

### 3. Intersection：先选择显式结果，再一次构造祖先闭包

先扫描显式项较少的一侧；显式数量相同则优先扫描总闭包较小的一侧。完全命中的普通集合直接 Copy；仅缺少至多 8 个标签且删除路径工作量较小时，复制后删除这些少量标签。

一般情况将命中的显式 ID 收集到结果显式索引缓冲中，按注册表 DFS ID 排序。先统计真实结果闭包大小，再发出每个不同祖先条目；条目暂存父 dense index，逆向归并时每个子条目只向父条目加一次贡献，最后一次性建立哈希索引。新结果的数组只按结果需求增长，不把被丢弃的候选闭包作为长期容量。

对于 M 个命中显式项、结果闭包 T，构造部分为期望 `O(M log M + T)`：排序和祖先归并是确定性的，最终哈希建桶为期望 `O(T)`。另加期望 `O(min(E左, E右))` 的成员选择。选择阶段允许输出与任一输入共享 storage：先保存命中 ID，再覆盖条目，保证接口引用、结构体代理和别名调用的语义。

少量删除快路径还要求删除路径总长度不超过候选闭包的一半，避免“复制几千层深链，再删除它，只留下一个浅标签”的容量浪费。计数来源也通过显式结果重建，保留存在性并正确恢复所有祖先贡献。

## 回退与适用边界

所有 43 项都保留在 [完整对照表](results/bulk/comparison.md)，包括：

- 无显式交集、两个输入各 1,024 项时，新结果从 **2.223 → 3.171 μs**；复用结果从 **2.291 → 2.914 μs**。有结果的批量构建收益不适用于空交集。
- 并集右侧为空时，从 **4.866 → 6.094 μs**；两个显式项的 128 层并集从 **1.180 → 1.269 μs**。空集合与小深链未全部变快。
- 50% 交集复用目标为 **17.468 → 17.273 μs**，改善很小；新交集更明显的收益包含减少首次构造和分配的影响。
- 新建空结果多 8 B；部分并集累计分配增加，见上表。没有发布内存降低到 Alex 水平或三项在所有输入上都更快的结论。
