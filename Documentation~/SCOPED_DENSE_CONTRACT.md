# Scoped Dense：合同与正确性依据

基线：PR15 的仅直接 Dense 输出实现。主候选提交 `2b2c87c156ff8287bde1cbb9b671f68917003c8f`；本文不修改被计时代码。

## 修改边界

`union` 仅在两个非空不同输入恰好一方 Dense、一方 Micro，且输出为不与输入重叠的 Micro 时生效。`copy` 仅在 Dense 源复制到 Micro 目标时生效。`combined` 是两项实际组合，不是按行选赢家。

公开验证、输入输出别名、普通 Clone 的容量和独立所有权、ReserveEntries 的增长策略保留。public Records、Enumerator、查询、AppendCore、RemoveTags、Builder 以及同表示位运算内核均不修改。Dense+Dense→Micro 仍为旧通用路径；原地别名仍为旧 AppendCore。公开 Dense 枚举也仍为原实现，不能把内部改进说成整个 foreach 已加速。

## 游标不变量

假设源集合满足既有合同：注册表冻结，索引有效，Dense 尾字的域外位为零，Count 准确；调用期间源不被并发修改。

私有 DenseRecordCursor 保存 words、next、pending。pending 为零时依次加载后续 ulong，跳过值为零的字。pending 非零时，以最低置位的位置向下对齐到16-ID边界，输出该位段的全部成员位，随后只从 pending 清除此位段。

由此：

1. next 之前的完整处理字不会再次加载；pending 只包含最后加载字中未发出的位段。
2. 每个非空位段恰好发出一次，且按全局编号升序。
3. 空字最多检查一次，不检查该字内部四个空位段；但仍会读取全域 W 个字，不能宣称只按非零字数量工作。
4. Low 只在 pending 非零时调用。offset 为0、16、32、48，移位不越过64位；旧 Micro32 编译限制没有在此被宣称修复。
5. 耗尽后不再推进越界。构造时只由已确认的 Dense 路径传入数组，不对内部已证明条件做重复校验。

该状态仅存在于物化调用的局部值类型中，不附加到公开枚举器或集合实例。局部栈、值复制和机器码仍有代价，必须实测。

## 混合并集

入口先处理注册表与别名、相同输入和空输入。专用方法清空独立 Micro 结果后，将 Dense 游标与有序 Micro 有效前缀归并。区间键小的一方直接输出；区间键相等时输出 OR，并累加两个成员掩码的交集基数。

每个键只发出一次，所以记录有序、非零且唯一。最终 Count = Dense.Count + Micro.Count - 重复成员数；同一区间的不相同成员位不会被当成重复。

输出仍调用旧 PutRecord，生成记录顺序与旧通用归并相同，因而保留原增长与实际结果容量足够就不扩容的合同。输入输出重叠不会进入此方法。脏目标的旧有效前缀被覆盖，剩余旧载荷在 used 之外，不属于成员。

## Dense→Micro CopyFrom

经过公开 Require 与自身复制检查后，仅为 Dense 源/Micro 目标进入专用方法。先 Clear，再发出占用记录；最后由原 CopyCore 的共同出口设置 source.Count。空源只清空有效成员，不缩容量，不扫描整个注册表。

没有借用源数组，没有延迟复制；目标后续修改不影响源。CopyAsStorage 自有物化方法没有改动；普通 Clone 没有改动。基准中的新建 CopyFrom 是真实 new Set + CopyFrom，不是把普通 Clone 换了名字。

## 性能合同

新并集和新建 CopyFrom 的所有对象、数组分配及准确 Count 均在计时内；Into/预分配 CopyFrom 单独列为0B合同。公开枚举/查询和同表示操作保留为不利测点检查，不能因为源码未变就删除稳定回退。

非空游标/归并仍为 O(W+B)，W为完整字数，B为局部记录量；主要减少常数项、通用分派和全结果重新计数，不声称把全域扫描变成只扫描非零记录。

实际验收以主 CI 的源码身份、完整原始样本、同二进制 A/A、生成机器码及所有负例为准。Linux .NET、Standard2.1宿主验证不代替 Unity/IL2CPP/Burst/真机测试。本文不是性能通过或生产迁移声明。
