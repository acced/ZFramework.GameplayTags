# 整数版 2.1.0-rc.1：安全性、序列化与热路径整理

本轮从用户上传的 `com.acced.zframework.gameplaytags-2.0.0-integer-optimized.tgz` 出发。其 SHA256 为 `dfc429acae4db5f3e3d37160567b41c6b09e8d07a6dfd84087e3e2c39a1cb6f4`。源码基于 `21e2d93` 加上传包的整数堆排序/祖先构造修改；`Tests~/Hardening/Baseline/Runtime` 保留换行规范化后的上传运行时，逐项哈希由 `Tools~/Hardening/materialized.json` 记录。

## 修复范围

- 缺少结构体回调时，单独反序列化的 GameplayTag 不再一律表现为 None。未绑定名称可按需解析，`Resolve()` 返回应缓存的规范句柄。修改公开 m_Name 后，规范名称引用检查会拒绝旧缓存 ID，并转入名称解析。结构仍只有一个字符串和一个整数，但热查询多了一次名称引用一致性检查；不是零成本。
- Unity/.NET 序列化回调不再初始化并冻结全局注册表。容器先保留名称，在正常访问时绑定。应用仍需在首次正常访问前显式 Initialize，特别是 AOT/裁剪项目。
- None 不会进入普通集合。计数的无效标签、非正数量、超额删除、根贡献溢出会拒绝；批量计数与内建父链先检查累计根贡献，重新挂接父节点先验证新增祖先的容量，防止可预测溢出后的半更新。
- 空的集合运算输入与 null 查询操作数有定义；null 实例调用不是受支持的查询方式，应使用泛型扩展/Utility。共享 Empty 的成员状态只读。
- 父链的自环和间接环被拒绝（内建父链）。事件初始观察者抛异常不再泄漏订阅；无效事件类型和空回调明确拒绝。
- 池租约有代际检查；复制的旧租约不能清空新借用者；默认租约 Dispose 无害；重复/跨线程归还拒绝，线程池保留数量有上限。容器增加了池元数据，这是额外对象载荷，不声称每容器内存降低。裸引用在归还后不得继续访问，代际租约不可能拦截任意裸引用操作。
- 负/过大容量在增长循环前拒绝，避免整数翻转和死循环。上限是实现边界，不保证该大小可以分配，OOM 不承诺事务回滚。
- 开发/检查构建枚举器检测修改；发行构建不增加版本字段和逐次版本检查。发行模式仍禁止修改中枚举，不保证 fail-fast。

## 保留的优化

保留上传版的哈希索引、显式索引和整数堆排序交集；普通首次加入时把自身贡献合入显式插入，祖先循环只访问严格祖先。稠密 Clear 使用活动桶前缀的批量清零，稀疏保留容量路径仍只访问占用桶。复制仍可复制有效桶前缀，避免无谓重建。没有引入每容器按注册表大小分配的数组。

安全检查有成本。本轮比较的是上传整数版与加固版，不是 rc.1，也不是历史计时结果的拼接。完整原始计时和所有回退记录由 qualification artifact 保存。没有“全部操作普遍更快”保证。

## 迁移与重要限制

这是整数路线，不是旧 name-based main/rc.1 的无缝替换。原 main 历史保留；rc.1 PR 分支不修改。包名 `com.acced.zframework.gameplaytags`、程序集和容器序列化字段不同，已有 name-based 项目必须显式迁移脚本和资源；不要同时安装两个同命名空间实现。

整数 2.0 的公开 `tag.m_Name` 字段保持不变，Unity 字段名和 Editor drawer 不需要迁移；.NET DataContract 仍保存同名字段。名称变化通过查询时的引用一致性检查处理，而不是依赖结构体序列化回调。真实 Unity 的 Inspector、Prefab 和场景往返仍必须由实际工程验收，便携桩编译不等于引擎执行。

在加载边界调用 `tag = tag.Resolve()` 并缓存。不要把未绑定、可编辑的标签当作长期哈希键。Unknown 名称在单标签回调中保留，解析 ID 为 0；容器仍只把已注册名称绑定为有效成员。注册表仍一进程/域一次初始化，不支持热替换；未实现 rc.1 的 Redirects/Settings API。

默认 foreach 仍枚举全部闭包条目；显式成员使用 GetExplicitTags()，输出无序，展示/网络需要顺序时显式排序。容器非线程安全。自定义父容器的异常与循环不受内建链预检查保证；父容器不得直接移除子容器拥有的贡献，不能在子容器仍挂接时任意清空其父。极长的容器父链仍有递归传播成本，标签树 3000 层测试不等于容器父链测试。

## 验证入口

`bash Tools~/Hardening/validate.sh <全新结果目录>`：既有随机/计数/别名/3000 层标签树测试，加固回归、上传版失败复现、netstandard2.1/C#9、源码生成器与 Unity 条件代码编译。上传版诊断故意打印 FAIL，不是候选测试豁免；候选任一失败都会使脚本失败。

`python3 Tools~/Hardening/benchmark.py <全新目录>`：每格独立进程，同机上传版/候选四对 AB/BA 平衡计时。只生成证据，不按计时阈值隐藏或丢弃失败性能格。真实 Unity 2022.3/Unity 6、Mono、IL2CPP 和设备性能尚未在本轮执行。
