# Packed operation milestone

This change specializes the prepared packed union, intersection and difference loops. It removes the per-record operation selector from these paths, keeps the existing contiguous-range kernels, and preserves independent ownership, eager Count, output aliases and actual-result capacity behavior. Small output buffers still use the general compactor; right-output difference keeps its protected exclusion path.

The source is the operation-only candidate from the completed local development comparison against Runtime commit `2fc862b91f9c53362e3fb63c7c086f7501c54ba9`. The experiment used the real public APIs, 16 independently allocated actors, three fresh-process rounds and two same-executable A/A labels per source. Seven samples per row retained actual output, immutable inputs, checksums, capacities, allocation counters and GC observations.

On the measured .NET 8.0.31 Linux x64 host, 130 of 192 forced-Compressed cases with explicit hardware kernels and 122 of 192 forced-portable cases were more than 5% faster in every matched-round source/A-A cross-comparison. Neither backend had a greater-than-5% regression in every such comparison. These comparisons are dependent descriptive checks, not confidence intervals. Process variation was material; short batches and all adverse observations remain in the evidence. This is targeted prepared-operation evidence, not a universal throughput or lifecycle claim. Forced-portable can still use System.Numerics and BCL acceleration.

All five tested execution configurations passed the public correctness, alias, capacity and prepared-allocation checks: normal .NET, hardware-disabled, forced-portable, a checked .NET library, and a separately compiled checked .NET Standard 2.1 library with an unchecked oracle host. The exact tested Runtime C# source was integrated here. The normal repository verification and new architecture-specific CI belong to this commit's checks, not to the preceding source snapshot.

The full earlier Runtime matrix remains relevant: its complete x64 and ARM64 run showed substantial gains against the original implementation, but explicit Bulk preparation still loses on several mixed-layout and short-lifecycle cases. This milestone does not claim those deficits are closed. New loading, local-run probing, metadata-layout and Block256 experiments remain separate until supported by their own results. Native Unity, IL2CPP and mobile execution are not covered by the managed-host measurements.

The repository-relative reproducer is in `Audit~/Refactor/PackedOperations`. It preserves the complete 372-row public-operation matrix and compares an exact local Git export of 2fc against the selected candidate Runtime, with both source-specific A/A labels and hardware/portable builds. Its default action stages immutable inputs; measurements require the explicit run action. Baseline preparation is local and does not fetch or mutate remotes.
