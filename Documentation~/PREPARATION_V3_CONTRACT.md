## 1. 一个候选，而不是拼接历史成绩

v3 的新建方法来自 PR13；覆盖重建的方法体、完整输入校验和填充链来自 PR12。生成器逐方法断言一致性。最终候选重新编译、重新计时。不能从旧表分别拿最好的新建和 Reset 数字充当 v3 数据。

当前实验仍是 Array/Dense 与 Micro/Dense 两个独立生成家族。没有统一三表示类型、Array↔Micro 桥接或自动选择器。普通查询、克隆、并集、追加、删除、注册表、序列化与 Editor 未改。

## 2. Reset 的异常保证

对已经存在的集合，必须先检查完整输入是否属于同一注册表、是否严格递增且唯一。最后一个输入非法，也不能先清空旧成员或先扩容。校验完成后才调用 EnsureCapacity、Clear、FillSortedHandles。

不在这个入口保留 v2 的空/单成员分派。它可能失去 v2 在极小输入上的收益，这是明确的代价，必须报告。恢复代码相同也不保证机器码和耗时完全相同，因此保留原版和同二进制 A/A。

## 3. Count==0 的独立转换

CopyAsStorage 的顺序是：

1. 检查目标表示和容量参数；Auto 不是合法目标。
2. 按 min(Registry.Count,max(Count,requestedCapacity)) 创建独立目标对象和对应存储。
3. 源 Count==0 时直接返回空目标，不读取源成员缓冲。
4. 非空时继续执行既有转换内核。

源 Count 与成员存储一致是现有集合不变量。新分配的目标已经为零，因此空源不需要扫描或清位。不能把这项退出放在参数校验之前，也不能返回源对象或共享空的可变包装器。

新 Dense 目标仍分配完整位图。消除源扫描不等于消除结果分配。普通克隆继续保留源 Capacity；显式转换使用自己的目标容量合同，没有用转换来替换原克隆基准。

## 4. 两种生命周期起点

### 输入起点 input

原材料是已经解析、排序且唯一的 RuntimeTag[]。

- keep：直接构造原表示，随后执行原公开并集。
- convert：构造原表示，再独立转换，再执行并集。
- direct：从同一输入直接构造目标表示，再执行并集。

三种策略的真实构造、校验、分配和计数全包含。输入排序/解析在此合同之外，不能将其称为乱序输入端到端成本。

### 现有集合起点 live

原材料是现有 Set。

- keep：使用现有集合，不添加无业务意义的克隆。
- convert：调用独立 CopyAsStorage。
- direct/rebuild：在计时内枚举源、分配导出 RuntimeTag[]，再构造目标。

live/keep/0 的结果就是原对象，不能用于独立新建结果的排行榜。其他准备结果和实际 Union 结果都是独立的。输入和对端只读。

每组使用完全相同的对端对象，且它保持原始源表示。不能让新方案免费得到理想目标表示的对端、而让保留方案承担不同条件。由此测到的混合表示运算成本也是模型必须支付的成本。

## 5. 不能从这些数据直接推导什么

这里的后续操作为 0、1、16 次独立 Union，不包含对不断变化结果的链式累积，也不是查询/追加/删除的加权真实战斗轨迹。逐项最快的强制表示只用于诊断，不是可部署的自动决策器。

输入创建、既有集合转换和普通克隆具有不同合同，必须分表。没有全局最佳阈值或全场景领先承诺。

A/A、原始 GC 计数、慢样本都保留；每轮 5% 是筛选规则而不是置信区间。长期峰值存活内存、冷缓存多角色轮换、真实 Unity/IL2CPP/Burst/手机设备验收尚不在本轮已执行范围内。
