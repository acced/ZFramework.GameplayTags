# Small independent rejection screens

These four-pair screens decide whether further qualification is worthwhile. A green job is completion, never optimization acceptance. Current fully qualified count remains **0/10**.

- **DrainedEventQueueReuse:** reuse an event array only when it is full and every queued notification has already been consumed. Exact reentrant notification order and pending-work growth remain covered. The prepared two-runtime screen measures first-use allocation/latency and repeated public cycles against the original already-grown queue. See [the fixed protocol](DrainedEventQueueReuse/README.md) and [all local evidence and limits](DrainedEventQueueReuse/LOCAL_EVIDENCE.md).
- **BindingRecordIds:** retain only the runtime ID and callback in each private binding record. This is separate from the held delegate-reuse candidate: both delegate constructions remain. Subscription ownership and event behavior are preserved, while unused mutable tag names may become collectible earlier. The selected screen checks lifecycle behavior, actual managed record size, first-use costs and seven existing warm/control paths.
- **EventCleanup:** skip a zero-length event-array clear after dispatch has already defaulted every consumed slot. Positive pending suffixes on callback exceptions still clear, and all state resets stay unconditional. Its historical cold-only package has no warm timing or pilot; the separate warm stage is preserved with the final stop decision below.
- **Bindings:** reuse one capturing callback delegate for both ownership tracking and registration, instead of constructing two equal delegates. The fixed screen covers fresh/reused bindings, multicast listeners, unaffected subscription/dispatch controls, and first-use time/allocation.
- **DenseClear:** dense active hash indexes use bulk zeroing, while small and sparse indexes retain occupied-slot clearing. A fixed twelve-row screen covers empty, mask0, threshold63/64/65, density127/128/129 and retained sparse states.
- **Callbacks:** counted notification lookup carries a fresh sorted-table cursor through each root-to-leaf mutation. Twelve fixed rows include dense/exhausted paths, global-only and silent controls, 8,192-entry gap/midpoint/miss guards, Clear and descending bulk reset. Original f7 is the comparator.
- **Registry:** new immediate-parent lookup for unique leaves beneath an existing trunk. Missing-parent construction retains the original prefix order and reuses its known-missing prefix. No new retained fields. Original f7 is the comparison source.
- **Hierarchical:** no-parent, non-alias bulk ingestion avoids the retained snapshot array after bounds prevalidation. Parent, self-alias and anomaly behavior remain covered by the focused correctness harness.

Each backend builds both exact sources on one runner, runs focused correctness, then four alternating before/after rounds. Registry and Hierarchical counts are frozen from the fastest observations among all four prior **baseline-only** local samples, targeting 200 ms and never reducing a count. Callbacks and DenseClear each use one original-only twelve-row pilot, then freezes one shared backend map before any candidate timing, also targeting 200 ms. Local screens and their adverse/uncertain results remain historical evidence. Short batches in the new run remain short; no confidence or global noninferiority claim is inferred from four rounds.

The SDK is 8.0.425, CoreCLR is 8.0.31 and the separate Mono job records its actual standalone Mono version. Unity Editor/Player, IL2CPP and Alex are not covered. Full correctness, cold allocation, retained-state and unrelated hot-path qualification remain mandatory for any surviving candidate.

Public artifacts contain only source/assembly hashes, runtime/compiler versions, CPU model, fixed configuration, numeric raw results and bounded status records. Private compiler output, absolute command paths, temporary files and environment dumps are not uploaded. Failure detail depends on the frozen package: the first BindingRecordIds Mono semantic failure published only bounded stage/count status, while child diagnostics stayed private. The separately reviewed diagnostic adds fixed child status/error codes and stream hashes without publishing arbitrary messages.

The earlier screen packages use a ten-minute internal limit and a fifteen-minute job limit. BindingRecordIds and DrainedEventQueueReuse use a five-minute internal limit; the preserved semantic diagnostics use two minutes, both within the same fifteen-minute job limit. These are hard bounds. An interrupted screen remains incomplete. No extra rounds, discarded samples or automatic full qualification is performed. The callback and dense-Clear pilots are single-shot and baseline-only; its actual short batches remain disclosed.
