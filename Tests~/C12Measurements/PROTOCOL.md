## Count selection, controls and interpretation rules

Calibrate only exact B1, before A/A or any contender samples. Start1024 calls, at most four pilots; target250ms, scale toward300ms. Ordinary cap is min(67,108,864, floor(2^30/[8*(sourceCount+targetCount+1)])); empty/single cells can obtain long batches while large mutation-heavy cells cannot wrap List version counters. Eight mutations per input/target element per workflow is a conservative bound for these kernels, including reset, tail cleanup and warmup; the2^30 ceiling leaves margin below signed32-bit. No live enumerator spans mutation. The maximum checksum is below calls*(8*(sourceCount+targetCount+1)+32), less than2^40 here, safely inside Int64. First-object/isolated pool cap8192; cold-process exactly one. Each cell's common count is frozen with hash and reused unchanged in A/A and every version. Pilot raw is retained. If the final pilot remains below250ms, mark inadequate. Do not quietly call a capped short pool adequate. Preprepared pure diagnostics and cold-process rows are diagnostic evidence only; they cannot establish full-workflow acceptance. Baseline pilot selection never observes contender speed. Numerical durations remain authoritative: faster contenders below250ms retain short status and are not discarded.

All four samples are retained, including outliers and GC. No favorable resampling, trimming, post-hoc threshold, component median subtraction, or subtraction of reset/observer cost. Any extra campaign requires separately frozen rules/output and preserves this one. Do not claim a speedup from point medians alone. Report paired per-block ratios, all absolute samples, min/max, median, paired signs, and exact4-pair sign-test limitations (four unanimous signs two-sided p=0.125 before multiplicity). This is not a multiple-comparison proof. A/A spread and unchanged-source controls constrain interpretation: a changed cell whose ratio variation overlaps these controls is unresolved. If material unchanged controls drift, report build/execution-context uncertainty rather than attributing it to C1/C2. Do not normalize or subtract controls to manufacture a speedup.

Inherited DOTNET_/COMPlus_/CORECLR_/COR_ switches are removed and recorded, effective runtime and LD_ settings are recorded; DOTNET_TieredCompilation=0 and COMPlus_TieredCompilation=0 for all children. Tiering is not an explanation. GC counters do not measure pause duration or establish causality. If attribution requires JIT/disassembly/CPU scheduling/GC traces, collect them in a separately labelled diagnostic run, never mix diagnostic timings into formal samples.

## Measured boundary and correctness

Retained workflow = CopyFrom(seed) restore + requested public operation + Count/last-name consumer. Its actual target state is restored each iteration; empty-source copy against nonempty target really clears a nonempty target every iteration. Copy workflows therefore include a reset CopyFrom and measured CopyFrom, with no component subtraction. New workflow = construct/build target at declared initial capacity + requested operation + consumer, every iteration; allocation includes setup. These represent whole public workflows, not pure kernels.

First-object and isolated diagnostics = pool preconstructed outside counters, one operation per untouched target, plus consumer, no timed reset. First-object refers to the target object, not process/JIT first use. Cold-process = one operation, no mutation warmup, includes first invocation/JIT where applicable, excludes registry/input construction. It is noisy descriptive evidence, never a throughput or zero-allocation acceptance substitute. The current harness still constructs containers using AddTag during setup; it does not claim first-ever assembly/JIT use.

Before counters, fixture setup and separate-object checks are untimed (except cold-process intentionally avoids mutation check); steady contexts warm64 operations. Counters enclose operation loop only. Timing, allocated bytes and GC deltas are captured, then raw numeric JSON is flushed before full validation. Validation checks every prepared target, all source/seed contents, strict sorted uniqueness, enumerated results, reference identity of Name representatives and cleared spare backing slots. Ordinary append/left-alias preserve target-side representatives; right-alias retains the explicit left input's representatives. Pool setup uses separately allocated equal strings. Validation failures leave raw and stderr intact and stop the stage. Initial semantic suite remains necessary for callback, invalid/uninitialized, serialization and exception behavior, which are not benchmark fixtures.

Postvalidation retained Count/capacity and array reference-slot payload are retained separately. Payload excludes object headers, strings, registry, whole heap and transient peak. No forced GC. New, low-capacity, first-object, cold-process and retained results are reported separately. No .NET8 Linux outcome certifies Unity Mono/IL2CPP/device performance.
