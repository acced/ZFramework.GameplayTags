# Final Runtime DLL protocol

Final broad measurements bind the validator-admitted baseline and candidate GameplayTags.dll files separately. The two source roots are runtime-integration/checked-guards/baseline/source/Runtime and runtime-integration/checked-guards/source/Runtime. Their shared scaffold includes the additive hierarchy/frozen-query bridge and the approved inherited checked-guard compatibility repairs; these shared changes are not attributed to upstream PR26. The baseline exact kernel and builders remain normalized from the selected PR26 experiment.

The host has a separate GameplayTags.Tests assembly so its untimed fixture can use the existing friend access for GameplayTagSettings.ReplaceAll. Every timed call is the public DirectArraySet API. Host source is identical for baseline and candidate. Cross-assembly inlining is enabled naturally and applies equally; no method-body substitution or private timing call is used.

Each run binds the exact candidate/baseline Runtime DLL, the same Unity test facade DLL, and its own host DLL. The runtime itself reports the loaded Runtime DLL path, SHA256 and MVID, and the runner checks the observed SHA/path against the bound identity. Full source, host, dependency and project hashes are retained. The facade supports standalone .NET execution of Runtime sources; it is not a Unity player run.

Probe.Reference.cs preserves the established direct public-call workload bodies and validation from Probe.Later.cs, adding only loaded-assembly identity reporting outside timing. Final query, builder and mixed groups use the same paired calibration,64MiB ceiling,>=1ms actual sample requirement, seven samples and three bracketed A/B/A rounds. Existing rejected variant data remain separate.

The bridge comparison is separately labeled and uses one exact candidate Runtime DLL for both APIs. It compares public frozenQuery.Matches(RuntimeTagSet) with directSet.Matches(frozenQuery), with identical registry, member handles, membership and frozen program. It is a fixed-actor, hot-query workload; construction/freezing occurs before timing. Sparse versus Micro storage is explicitly reported, and Auto may choose Dense for large actors in this smaller registry.

The bridge has18 rows per requested Micro/Dense/Auto mode: actors with 8/4096 members times exact hit/miss, parent-range hit/miss, nested pass/fail, empty query, empty-All constant true, and charged remove→public match→add→public match. The nested cases exercise Any,All andNo clauses. The mutation row includes both mutations and both public matches; every other logical operation includes64 public matches. Neither caller receives a free per-call conversion/capture. Warm allocation must remain 0 B, all actor membership is revalidated, and known true/false results are consumed and checked.

Small native JIT captures on the exact bound DLLs are separate untimed diagnostics. They retain emitted method headers and identify missing/inlined methods honestly. Captures do not enter accepted timing summaries or substitute for measured behavior.

The first completed reference builder/default run and native captures initially recorded pre-guard source-root metadata while already binding the correct repaired final DLL hashes. This metadata-only error was reconciled against the actual compiler build-binding and sources.after manifests before acceptance. Original metadata is retained beside corrected identities; no DLL, command, raw sample or native text changed. See reference-source-reconciliation.json. Future reference builds reject a source root that differs from the compiler binding.
