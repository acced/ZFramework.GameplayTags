# 批量构造实验：契约、成本与迁移边界

实现提交：`6c7e18dadf6b384046249ba951227109e8d36fde`。此文档不改变已提交的计时源码。测试结果另行记录；在结果审核完成之前不声称获得性能收益。

## 本轮解决的问题

PR11 的构建夹具已持有有序且唯一的标签句柄，仍逐项调用 AddTag。这里把批量准备与动态单项修改分开：验证完整输入，然后直接写出一种表示。保留既有直接复制构造、DenseFusion、查询和集合运算内核。并未实现自动表示选择器或新的局部容器。

## 三个新入口

### FromSortedUnique

示意调用：`RuntimeTagSet.FromSortedUnique(registry, sortedTags, capacity, storage)`。

输入为 `ReadOnlySpan<RuntimeTag>`。句柄必须全部由给定的同一注册表产生，并按 RuntimeIndex 严格递增；重复、逆序、默认句柄、其他注册表的句柄均被拒绝。默认空 Span 表示空输入。调用期间不得并发修改输入。

先检查参数和整段输入，随后才分配最终集合。结果独立拥有成员缓冲；调用结束后，外部标签数组可以被修改或释放，不影响结果。不会保存指向外部数组的“已验证”包装器。

对 Array，从每个已验证句柄直接写入 ID；这不是对 RuntimeTag[] 进行原始内存拷贝，因为该数组还包含注册表引用。对 Dense，将同一个 ulong 对应的成员位先合并，再写入一次。对 Micro，将同一区间的成员合并为一条地址＋掩码记录。唯一输入的长度就是准确 Count，不需要再次全图计数。

### ResetFromSortedUnique

示意：`existing.ResetFromSortedUnique(sortedTags)`。

覆盖而非追加。先验证全部输入，验证成功后才允许扩容、清空或写入。最后一个输入无效也不能造成半清空结果。已有容量足够时不分配；容量不足时仍按旧容量策略显式扩容，不隐式切换表示。Dense 输出中旧的未命中字必须清除；Array/Micro 的未使用尾部不参与成员判断。

输入是外部标签句柄，不是可直接访问的内部成员缓冲，因此不能与私有 ID/位图数组形成存储别名。线程模型不变：不支持并发修改和修改中枚举。

### FromUnordered

接受乱序和重复标签，但同样拒绝默认/外域句柄。拥有一个临时 int[] 工作区，将句柄解析为已知 ID，再排序、原地去重，直接写出独立结果。调用方数组不被排序或修改。

工作区不是对象池，也不是隐藏的准备阶段；它的分配、排序、去重和最终分配全部计入此调用。本实验故意保留可解释的统一排序候选，不把它假定为所有表示、所有规模上的最佳乱序算法。Dense 原有逐项置位可能在乱序输入上更合适，必须保留对照和不利结果。

## 容量合同

最终预约成员容量按 `min(registry.Count, max(requestedCapacity, rawInputLength))` 确定，与本轮预设容量后反复 AddTag 的对照相同。不能靠把重复项压缩后的较小数量改作容量而得到不公平的分配优势。

Micro 继续保留原来按任意成员分布预约容量的规则，而不只承诺当前集中分布。已有 Micro16 的 2^20 个注册编号限制没有扩大，也没有套在 Array/Dense 上。它仍然是实验表示，不是整个库的新全局约束。

## 内部信任与外部验证

私有分配构造器只由已验证的新入口调用，接收已夹紧容量和确定的 Dense/Array 选择，不再次检查注册表、枚举值或同一输入。私有写入循环只消费当前调用内已经校验的句柄，或当前方法独立拥有、刚排序去重的 ID 工作区。

RuntimeTag 的合法 ID 由现有注册表发放边界保证，因此不在每次填充中重新 GetTagAt 或查字符串。新入口仍需检查每个外部句柄的所有者和有序性。开发期断言不替代这些外部检查。

旧 AddTag 默认句柄返回 false 的行为没有变化。新严格 Builder 拒绝默认句柄，是新 API 的明示契约，不能声称它与所有无效输入下的旧循环完全等价。性能对照仅使用两者共同接受的有效输入。

## 计量边界

- 有序新建：完整验证、所有分配、写入和准确 Count 全部计时；预设容量的旧循环保留。
- 乱序/重复新建：额外工作区、排序和去重全部计时，不借用已经排序的计时外副本。
- 预分配覆盖：独立列出，要求真实 0 B，不以“没有 GC 回收”代替分配计数。
- 建立输入后执行 1/16 次并集：这是显式的生命周期组合，不是原来的独立 Union 指标。
- 原来的精确查询、独立 Union、真实复制后追加和真实复制后删除的内核没有改动。本轮不能用 Builder 的收益替代四项指标全面领先的验收。

## 可解释的工作量

已排序唯一输入含 N 个句柄：边界验证为 O(N)。Array 填充为 O(N)；Dense 填充为 O(N)，但新分配和清空仍有全域 W 个字的成本；Micro 填充为 O(N)，其预约数组长度仍按容量合同计算，不等于当前有效记录数。

一般输入含 M 个句柄：额外包含 O(M) 工作区、排序、去重及物化。复杂度只能描述工作量，不可直接拿 N、W、logN 相加当作纳秒模型。

## 版本与发布状态

修改仍位于 Audit~ 的独立候选中。运行时实例没有新增字段、缓存或第二份成员表示。现有序列化、Editor、Query、包版本与最低 Unity 声明保持不变。

本轮使用显式固定 SDK8.0.425 的 Linux .NET8 x64/ARM64 测试及独立 Standard2.1 库测试；它们不能替代 Unity2021.3、Mono、IL2CPP、Burst、Android/iOS 或真机验收。选择器、转换成本、Run 容器、长期内存峰值与全历史竞争库排名不在本轮完成范围内。
