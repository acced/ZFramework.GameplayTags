# Count == used：单置位记录路径的实际验证

日期：2026-10-01。PR #9。**正确性已验证，性能不是全平台统一获益。没有生产迁移、合并或发布。**

## 结论

- 数学不变量成立，专用实现通过两平台完整测试。仅适用于规范 Micro 记录，不适用于 Dense 的 used 字段。
- `SingleRemoveSet` 只增加删除专用路径：ARM64 有明确收益；x64 的目标单置位子组没有达到每轮 5% 的稳定收益门槛。保留为进一步定位/集成的候选，不按 CPU 名称直接硬编码启用，也不称为跨平台验收通过。
- `SingleBitSet` 同时改并集/追加/删除：并集有局部收益，但追加有多项回退。本轮不采用这个组合。并集单独保留且删除追加分支后的代码布局尚未独立测量，不能称为已验证的第三个赢家。
- 生产仍保持旧 Auto。不能将本轮某一个平台、某一个合同的赢家拼接成全面领先的实现。

## 不变量与实现

设第 i 条有效 Micro 记录的成员位数为 c_i。规范记录满足 c_i>=1，Count=sum(c_i)，used=记录数，因此 Count==used 当且仅当所有 c_i==1。

删除只清除成员，不增加任何位。左侧单置位时，每条记录要么原样保留，要么整条消失；结果 Count 就是 surviving used。右侧可以多置位。省掉的是每次命中后的 PopCount 和 removedBits 累计，没有推迟计数。

并集/追加不保持单置位性质。同一区间的两个不同位合并后是一条记录、两个成员。因此继续使用 a.Count+b.Count-duplicates。任意一侧单置位时，交集掩码的位数至多为1，重复数可以由非零判断得到。

本轮由原 DirectArray 生成三份字面源码：

| 类 | 唯一新增变化 |
|---|---|
| DirectControlSet | 对照，PR8 DirectArray 改类名而已 |
| SingleRemoveSet | 仅在已确认的 Micro 双数组删除路径中分派 Count==used 专用循环 |
| SingleBitSet | 在删除优化之外，再对独立数组归并和原地反向追加简化重复位计数 |

无新增对象字段/缓存/标志/原始成员ID列表/对象池/COW/共享可变结果。容量公式、CountRecords 预扫描、复制、结果所有权、公开验证、别名、混合表示均保留。查询和 Dense 内核源码不变。付出的代价是额外入口分派与专用循环代码，不是零复杂度升级。
